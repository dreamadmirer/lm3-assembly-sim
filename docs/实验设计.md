# LM3 协作机器人仿真实验（2 个）

适用对象：机器人工程 / 自动化专业本科三年级以上，已修《机器人学基础》。
平台：本仿真实验平台（浏览器打开 `index.html`），任务程序面板按官方 `lebai_sdk` 语义执行。
配套文档：`docs/SDK对齐说明.md`。

每个实验都给出「界面应展示什么」，用于教师二次开发或检查现有界面是否满足自学需要。

## 实验一　点位运动与直线抓放（基础，60–90 min）

### 1.1 实验目标
1. 区分关节空间运动 `movej` 与笛卡尔直线运动 `movel`，能解释两者轨迹差异。
2. 会读 `Q`（关节角，rad）与 `WP`（末端位姿，m/rad）两组路径点，能修改其中 1–2 个数值并复现。
3. 理解 `movej(p, a, v, t, r)` 中 **t > 0 时 a、v 失效** 的优先级规则。
4. 会用 `set_claw(force, amplitude)` 控制夹爪，理解 amplitude 是"占最大行程的百分比"。
5. 能用日志与 `get_kin_data()` 反馈定位"没抓到 / 抓歪了 / 撞桌面"的原因。

### 1.2 相关知识
- **两种运动**：`movej` 在关节空间插值，末端轨迹是曲线；`movel` 让 TCP 走直线，姿态同时插值，适合接近/离开工件的最后一段。
- **坐标系**：平台位姿均为**基座坐标系**；`rx=3.1416` 表示工具 z 轴垂直向下（即"手心朝下"）。
- **单位**：关节角 rad（`3.1416 ≈ 180°`），位置 m，姿态 rad；`movel` 的 a/v 是 m/s²、m/s，`movej` 的是 rad/s²、rad/s。
- **夹爪**：`amplitude=100` 为最大开口（95 mm），`0` 为闭合；夹紧时 amplitude 应略小于工件宽度对应值，力度 `force` 取 20–80 足够夹住塑料件。
- **状态机**：`IDLE`（空闲）→ `MOVING`（运动中）→ 急停 `ESTOP`。

### 1.3 任务流程
1. 左侧列表选择「立方块」，观察右下角自动生成的程序与 3D 视图中的路径点。
2. 记录一次默认运行的节拍（右下角提示条显示 `执行完成 · x.xs`）。
3. 只把 `T_JOINT` 改为 0.600 再运行，比较节拍与启动/停止的"顿挫感"。
4. 把 `T_JOINT` 改回 1.200，再把 `A_JOINT`、`V_JOINT` 改大（如 1.5 / 1.2）后运行，观察**节拍不变**——验证 t>0 时 a/v 被忽略。
5. 修改 `WP['grasp']` 的 `z`（如 +0.010），运行并观察"夹爪闭合但工件未跟走"。
6. 修改 `GRIP_AMP`（如调大 8–10），运行并观察夹持是否仍然成功；再故意调到 20 观察空夹。
7. 用 `#` 注释掉 `robot.wait_move()` 中的一行，运行并解释为什么动作会"叠在一起"。

### 1.4 编程提示
- 只改数字，不要改 `Q`/`WP` 的键名；键名与 `movej(Q['…'])` 必须一一对应，否则报 `Q 中未定义路径点`。
- `T_JOINT`、`T_LINEAR` 是"运动时间"，`A_*`、`V_*` 是"加速度/速度"；同一段运动只让一组起作用。
- 抓取高度由 `WP['grasp'].z` 决定，建议每次只改 ±0.01 m。
- 夹爪闭合用 `set_claw(GRIP_FORCE, GRIP_AMP)`，张开用 `set_claw(20, 100)`。

### 1.5 调试检查点（自检清单）
| 现象 | 优先检查 | 判定 |
| --- | --- | --- |
| 提示 `Q 中未定义路径点` | `Q` 字典是否被改坏（键名/元素个数） | 每个键必须是 6 个数 |
| 提示 `[1001] Jx 超出安全范围` | `Q` 的关节角或 `WP` 的 z 是否过大 | 角度换算成度是否超过 ±170° |
| 提示 `[1002] 目标位姿不可达` | `WP` 的 x/y/z 是否超出臂展 | 改回默认值能跑通 |
| 夹爪闭合但工件不动 | `grasp` 的 z 偏高 / 偏低 | 3D 中夹爪是否包住工件中部 |
| 工件被"推走" | `approach` 的 z 太低 | 预抓取点应高于工件 80–150 mm |

### 1.6 预期现象
- 改小 `T_JOINT`：整体更快，起点与终点出现明显急停急起（因为 t 定时，速度被拉高）。
- 只改 `A_JOINT/V_JOINT`（t 仍 > 0）：**节拍完全不变**，验证优先级。
- `grasp.z` 抬高 10 mm：夹爪在工件上方闭合，日志出现"未检测到工件"，提升时工件留在桌面。
- `GRIP_AMP` 过小：夹爪张开不足，靠近工件时会把工件顶开。

### 1.7 验收标准（满足 4/5 即通过）
1. 能复现一次完整抓放，日志出现"夹爪夹紧 · 立方块"与"工件已放入 A 盒"。
2. 能口头/书面解释 `movej` 与 `movel` 的差别，并指出程序中各自出现的位置。
3. 完成"t>0 时 a/v 失效"的对照实验，并给出两次节拍数据。
4. 至少复现 1 种失败现象，并用日志定位到具体参数。
5. 提交修改后的程序片段与 3 行以内的结论。

### 1.8 实验界面应展示
- **知识卡**（右上抽屉，可折叠）：两种运动对比图（曲线 vs 直线）、单位换算表（rad↔deg）、`t>0` 优先级说明。
- **操作引导**：步骤式清单（1–7），当前步骤高亮；每步给出"做什么 / 看什么"。
- **提示**：改参数时在代码面板下方显示"你正在修改 T_JOINT：单位 s，必须 > 0"；错误时给出**原因 + 建议改法**，而不只是错误码。
- **反馈**：状态灯 `IDLE/MOVING/ESTOP`；节拍条；日志中夹爪开合毫米数；成功/失败计数。
- **自检**：五个检查点做成可勾选清单，勾选后显示对应"该看哪里"的提示。

## 实验二　自动分拣、异常处理与急停恢复（进阶，90–120 min）

### 2.1 实验目标
1. 用 `movej/movel/set_claw` 组合完成"取—运—放"循环，并按形状/类别分流到 A、B 盒。
2. 理解并实现**异常处理**：`try / except / finally`，确保任何失败路径都能 `stop_sys()` 停机。
3. 理解并演练**急停安全流程**：`ESTOP` → 复位（`stop_sys` + `start_sys`）→ 继续作业。
4. 能通过 `get_robot_state()`、`get_kin_data()`、日志三处交叉验证机器人当前状态。
5. 分析一次失败（抓空/放偏/超限），给出参数级修复方案。

### 2.2 相关知识
- **任务级流程**：规划（路径点）→ 执行（运动队列）→ 反馈（状态/日志）→ 异常收敛。
- **运动队列**：`movej/movel` 立即返回 `motion_id`，指令按序排队；`wait_move()` 阻塞到全部完成，是"分段调试"的关键。
- **异常分类**：语法/解析错误（运行前拦截，带行号）、运动学错误 `[1002]`、关节超限 `[1001]`、状态错误 `[1003] 急停中`、未连接 `[1004]`。
- **安全流程**：实机上急停由安全回路切断动力；软件侧要"停止运动 → 记录现场 → 复位 → 重新使能"。
- **分拣规则**：回转体（圆柱/球）→ A 盒，多面体（立方/六棱/三棱/L 形）→ B 盒。

### 2.3 任务流程
1. 先跑「一键全部分拣」，记录 6 件工件的节拍与成功率。
2. 打开任务程序，为单件任务补全 `try/except/finally`（模板已给，要求解释每一段作用）。
3. 人为制造 **3 类故障**并记录报错码与恢复动作：
   - a) 把某路径点 z 改到 1.15（不可达）；
   - b) 把某关节角改到 4.0 rad（超限）；
   - c) 运行中点击「急停」。
4. 每次故障后执行"复位 → 重新运行"，确认能继续作业。
5. 编写一段"失败重试"逻辑（伪代码即可）：抓空时重新下降 20 mm 再夹一次。
6. 统计：6 件分拣的完成数、平均节拍、失败次数，并分析瓶颈路径点。

### 2.4 编程提示
- 捕获异常时不要 `except: pass`，至少打印 `e`（仿真会给出 `[码] 说明`）。
- `finally` 中必须调用 `robot.stop_sys()`；这是"任何路径都安全停机"的保证。
- 状态判断用 `get_robot_state()`，不要靠"等几秒"猜测。
- 急停后不要直接发运动指令，先复位（`stop_sys` → `start_sys`）。
- 分拣顺序建议"由近到远"，减少转运距离与关节换向。

### 2.5 调试检查点
| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 程序"跑一半没反应" | 缺 `wait_move()`，指令排队但界面无反馈 | 每条运动后加 `wait_move()` |
| `[1003] 急停中` | 急停未复位 | 点「复位」，或 `stop_sys()+start_sys()` |
| 放置后工件压在盒沿 | `place.z` 偏高或放置点偏出盒内 | 减小 `PLACE_Z`，检查 `WP['place']` 的 x/y |
| 成功率 < 100% | 抓取高度/夹持宽度不匹配 | 按工件尺寸重算 `GRIP_AMP` |
| 分拣后计数不变 | 未落在盒内判定区 | 放置点须在盒内 12 mm 边距以内 |

### 2.6 预期现象
- 补全 `try/except/finally` 后，任何异常都会打印 `任务异常：[码] …` 且结尾出现 `stop_sys()` 日志。
- 急停时：状态灯变红 `ESTOP`，程序提示"运动被停止（急停 / stop_move），程序中止"，按钮变「复位」。
- 复位后：状态回到 `IDLE`，可立即重新运行。
- 3 类故障都能在 3 分钟内定位到具体行/参数。

### 2.7 验收标准（满足 4/5 即通过）
1. 6 件分拣全部完成，或给出未完成件的失败原因与修复方案。
2. 提交带 `try/except/finally` 的完整程序，并能解释 `finally` 的必要性。
3. 现场演示一次急停 → 复位 → 继续运行，全程状态灯变化正确。
4. 至少复现并修复 2 类异常，附报错码与修改前后参数。
5. 给出节拍统计表（单件/平均/瓶颈），并提出 1 条优化建议。

### 2.8 实验界面应展示
- **知识卡**：状态机图（IDLE/MOVING/ESTOP）、错误码速查表（1001/1002/1003/1004/1005）、`try/except/finally` 执行顺序示意。
- **操作引导**：故障演练卡片（3 个），每张卡给"如何制造 → 预期报错 → 如何恢复"。
- **提示**：代码面板顶部常驻"运行前自检"三条：有 `wait_move`？有 `finally: stop_sys()`？急停是否已复位？
- **反馈**：实时状态灯 + 当前步骤高亮 + 完成/失败计数 + 平均节拍；异常时在日志上方弹出"错误码 + 一句话建议"。
- **复盘**：运行结束后给出小结（用时、完成件数、异常次数、最慢路径点），便于写实验报告。
