# LM3 协作机器人仿真实验（6 个）

适用对象：机器人工程 / 自动化专业本科三年级以上，已修《机器人学基础》。
平台：本仿真实验平台（浏览器打开 `index.html`），任务程序面板按官方 `lebai_sdk` 语义执行。
配套文档：`docs/SDK对齐说明.md`。

六个实验按难度递进：基础（一、二）→ 中等（三、四）→ 中高（五）→ 综合（六）。
每个实验都给出「界面应展示什么」，用于教师二次开发或检查现有界面是否满足自学需要。

## 实验一　点位运动与直线抓放（基础，60–90 min）

### 1.1 实验目标
1. 区分关节空间运动 `movej` 与笛卡尔直线运动 `movel`，能解释两者轨迹差异。
2. 会读 `Q`（关节角，rad）与 `WP`（末端位姿，m/rad）两组路径点，能修改其中 1–2 个数值并复现。
3. 理解 `movej(p, a, v, t, r)` 中 **t > 0 时 a、v 失效** 的优先级规则。
4. 会用 `set_claw(force, amplitude)` 控制夹爪，理解 amplitude 是"占最大行程的百分比"。
5. 能用日志与 `get_kin_data()` 反馈定位"没抓到 / 抓歪了 / 撞桌面"的原因。

### 1.2 相关知识
- **两种运动**：`movej` 在关节空间插值，末端轨迹是曲线；`movel` 让 TCP 走直线，姿态同时插值，适合接近/离开工件的最后一段。
- **坐标系**：平台位姿均为**基座坐标系**；`rx=3.1416` 表示工具 z 轴垂直向下（即"手心朝下"）。
- **单位**：关节角 rad（`3.1416 ≈ 180°`），位置 m，姿态 rad；`movel` 的 a/v 是 m/s²、m/s，`movej` 的是 rad/s²、rad/s。
- **夹爪**：`amplitude=100` 为最大开口（95 mm），`0` 为闭合；夹紧时 amplitude 应略小于工件宽度对应值，力度 `force` 取 20–80 足够夹住塑料件。
- **状态机**：`IDLE`（空闲）→ `MOVING`（运动中）→ 急停 `ESTOP`。

### 1.3 任务流程
1. 左侧列表选择「立方块」，观察右下角自动生成的程序与 3D 视图中的路径点。
2. 记录一次默认运行的节拍（右下角提示条显示 `执行完成 · x.xs`）。
3. 只把 `T_JOINT` 改为 0.600 再运行，比较节拍与启动/停止的"顿挫感"。
4. 把 `T_JOINT` 改回 1.200，再把 `A_JOINT`、`V_JOINT` 改大（如 1.5 / 1.2）后运行，观察**节拍不变**——验证 t>0 时 a/v 被忽略。
5. 修改 `WP['grasp']` 的 `z`（如 +0.010），运行并观察"夹爪闭合但工件未跟走"。
6. 修改 `GRIP_AMP`（如调大 8–10），运行并观察夹持是否仍然成功；再故意调到 20 观察空夹。
7. 用 `#` 注释掉 `lebai.wait_move()` 中的一行，运行并解释为什么动作会"叠在一起"。

### 1.4 编程提示
- 只改数字，不要改 `Q`/`WP` 的键名；键名与 `movej(Q['…'])` 必须一一对应，否则报 `Q 中未定义路径点`。
- `T_JOINT`、`T_LINEAR` 是"运动时间"，`A_*`、`V_*` 是"加速度/速度"；同一段运动只让一组起作用。
- 抓取高度由 `WP['grasp'].z` 决定，建议每次只改 ±0.01 m。
- 夹爪闭合用 `set_claw(GRIP_FORCE, GRIP_AMP)`，张开用 `set_claw(20, 100)`。

### 1.5 调试检查点（自检清单）
| 现象 | 优先检查 | 判定 |
| --- | --- | --- |
| 提示 `Q 中未定义路径点` | `Q` 字典是否被改坏（键名/元素个数） | 每个键必须是 6 个数 |
| 提示 `[1001] Jx 超出安全范围` | `Q` 的关节角或 `WP` 的 z 是否过大 | 角度换算成度是否超过 ±170° |
| 提示 `[1002] 目标位姿不可达` | `WP` 的 x/y/z 是否超出臂展 | 改回默认值能跑通 |
| 夹爪闭合但工件不动 | `grasp` 的 z 偏高 / 偏低 | 3D 中夹爪是否包住工件中部 |
| 工件被"推走" | `approach` 的 z 太低 | 预抓取点应高于工件 80–150 mm |

### 1.6 预期现象
- 改小 `T_JOINT`：整体更快，起点与终点出现明显急停急起（因为 t 定时，速度被拉高）。
- 只改 `A_JOINT/V_JOINT`（t 仍 > 0）：**节拍完全不变**，验证优先级。
- `grasp.z` 抬高 10 mm：夹爪在工件上方闭合，日志出现"未检测到工件"，提升时工件留在桌面。
- `GRIP_AMP` 过小：夹爪张开不足，靠近工件时会把工件顶开。

### 1.7 验收标准（满足 4/5 即通过）
1. 能复现一次完整抓放，日志出现"夹爪夹紧 · 立方块"与"工件已放入 A 盒"。
2. 能口头/书面解释 `movej` 与 `movel` 的差别，并指出程序中各自出现的位置。
3. 完成"t>0 时 a/v 失效"的对照实验，并给出两次节拍数据。
4. 至少复现 1 种失败现象，并用日志定位到具体参数。
5. 提交修改后的程序片段与 3 行以内的结论。

### 1.8 实验界面应展示
- **知识卡**（右上抽屉，可折叠）：两种运动对比图（曲线 vs 直线）、单位换算表（rad↔deg）、`t>0` 优先级说明。
- **操作引导**：步骤式清单（1–7），当前步骤高亮；每步给出"做什么 / 看什么"。
- **提示**：改参数时在代码面板下方显示"你正在修改 T_JOINT：单位 s，必须 > 0"；错误时给出**原因 + 建议改法**，而不只是错误码。
- **反馈**：状态灯 `IDLE/MOVING/ESTOP`；节拍条；日志中夹爪开合毫米数；成功/失败计数。
- **自检**：五个检查点做成可勾选清单，勾选后显示对应"该看哪里"的提示。

## 实验二　自动分拣、异常处理与急停恢复（进阶，90–120 min）

### 2.1 实验目标
1. 用 `movej/movel/set_claw` 组合完成"取—运—放"循环，并按形状/类别分流到 A、B 盒。
2. 理解并实现**异常处理**：`try / except / finally`，确保任何失败路径都能 `stop_sys()` 停机。
3. 理解并演练**急停安全流程**：`ESTOP` → 复位（`stop_sys` + `start_sys`）→ 继续作业。
4. 能通过 `get_robot_state()`、`get_kin_data()`、日志三处交叉验证机器人当前状态。
5. 分析一次失败（抓空/放偏/超限），给出参数级修复方案。

### 2.2 相关知识
- **任务级流程**：规划（路径点）→ 执行（运动队列）→ 反馈（状态/日志）→ 异常收敛。
- **运动队列**：`movej/movel` 立即返回 `motion_id`，指令按序排队；`wait_move()` 阻塞到全部完成，是"分段调试"的关键。
- **异常分类**：语法/解析错误（运行前拦截，带行号）、运动学错误 `[1002]`、关节超限 `[1001]`、状态错误 `[1003] 急停中`、未连接 `[1004]`。
- **安全流程**：实机上急停由安全回路切断动力；软件侧要"停止运动 → 记录现场 → 复位 → 重新使能"。
- **分拣规则**：回转体（圆柱/球）→ A 盒，多面体（立方/六棱/三棱/L 形）→ B 盒。

### 2.3 任务流程
1. 先跑「一键全部分拣」，记录 6 件工件的节拍与成功率。
2. 打开任务程序，为单件任务补全 `try/except/finally`（模板已给，要求解释每一段作用）。
3. 人为制造 **3 类故障**并记录报错码与恢复动作：
   - a) 把某路径点 z 改到 1.15（不可达）；
   - b) 把某关节角改到 4.0 rad（超限）；
   - c) 运行中点击「急停」。
4. 每次故障后执行"复位 → 重新运行"，确认能继续作业。
5. 编写一段"失败重试"逻辑（伪代码即可）：抓空时重新下降 20 mm 再夹一次。
6. 统计：6 件分拣的完成数、平均节拍、失败次数，并分析瓶颈路径点。

### 2.4 编程提示
- 捕获异常时不要 `except: pass`，至少打印 `e`（仿真会给出 `[码] 说明`）。
- `finally` 中必须调用 `lebai.stop_sys()`；这是"任何路径都安全停机"的保证。
- 状态判断用 `get_robot_state()`，不要靠"等几秒"猜测。
- 急停后不要直接发运动指令，先复位（`stop_sys` → `start_sys`）。
- 分拣顺序建议"由近到远"，减少转运距离与关节换向。

### 2.5 调试检查点
| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 程序"跑一半没反应" | 缺 `wait_move()`，指令排队但界面无反馈 | 每条运动后加 `wait_move()` |
| `[1003] 急停中` | 急停未复位 | 点「复位」，或 `stop_sys()+start_sys()` |
| 放置后工件压在盒沿 | `place.z` 偏高或放置点偏出盒内 | 减小 `PLACE_Z`，检查 `WP['place']` 的 x/y |
| 成功率 < 100% | 抓取高度/夹持宽度不匹配 | 按工件尺寸重算 `GRIP_AMP` |
| 分拣后计数不变 | 未落在盒内判定区 | 放置点须在盒内 12 mm 边距以内 |

### 2.6 预期现象
- 补全 `try/except/finally` 后，任何异常都会打印 `任务异常：[码] …` 且结尾出现 `stop_sys()` 日志。
- 急停时：状态灯变红 `ESTOP`，程序提示"运动被停止（急停 / stop_move），程序中止"，按钮变「复位」。
- 复位后：状态回到 `IDLE`，可立即重新运行。
- 3 类故障都能在 3 分钟内定位到具体行/参数。

### 2.7 验收标准（满足 4/5 即通过）
1. 6 件分拣全部完成，或给出未完成件的失败原因与修复方案。
2. 提交带 `try/except/finally` 的完整程序，并能解释 `finally` 的必要性。
3. 现场演示一次急停 → 复位 → 继续运行，全程状态灯变化正确。
4. 至少复现并修复 2 类异常，附报错码与修改前后参数。
5. 给出节拍统计表（单件/平均/瓶颈），并提出 1 条优化建议。

### 2.8 实验界面应展示
- **知识卡**：状态机图（IDLE/MOVING/ESTOP）、错误码速查表（1001/1002/1003/1004/1005）、`try/except/finally` 执行顺序示意。
- **操作引导**：故障演练卡片（3 个），每张卡给"如何制造 → 预期报错 → 如何恢复"。
- **提示**：代码面板顶部常驻"运行前自检"三条：有 `wait_move`？有 `finally: stop_sys()`？急停是否已复位？
- **反馈**：实时状态灯 + 当前步骤高亮 + 完成/失败计数 + 平均节拍；异常时在日志上方弹出"错误码 + 一句话建议"。
- **复盘**：运行结束后给出小结（用时、完成件数、异常次数、最慢路径点），便于写实验报告。

## 实验三　运动学与工具坐标（中等，60–90 min）

### 3.1 实验目标
1. 说清"关节角"与"TCP 位姿"的关系，会用 `kinematics_forward` / `kinematics_inverse` 互相换算。
2. 理解位姿是基座坐标系，`rx=3.1416` 表示工具 z 轴朝下；会通过改 `rx` 改变夹爪朝向。
3. 会用 `pose_trans(base, offset)` 生成"沿工具坐标系偏移"的接近点，并解释它和直接改 z 的区别。
4. 建立可达性概念：什么时候反解无解，仿真为什么报 `[1002]`。

### 3.2 相关知识
- 正解：给定 6 个关节角，算出唯一 TCP 位姿；反解：给定位姿，求关节角（可能多解，也可能无解）。
- 单位为 m / rad；`0.1 rad ≈ 5.7°`，`π ≈ 3.1416 ≈ 180°`。
- `pose_trans` 的偏移量是"工具坐标系下的量"，工具朝下时 `z+0.05` 是"沿手的方向再伸 50 mm"。
- 奇异点（腕部伸直、J5≈0）附近反解会剧烈跳变或直接失败，实机上要避开。

### 3.3 任务流程
1. 运行一次默认程序，把日志里的关节角、TCP 数值与右侧「实时状态」逐项对照。
2. 在 `print` 里用 `kinematics_inverse(WP['grasp'], Q['approach'])` 反解抓取点，与 `Q['grasp']` 比较（通常只差零点几度）。
3. 把 `APPROACH_OFFSET` 的 `'z'` 从 `0.050` 改成 `0.120`，看 `pose_trans` 打印的接近点如何变化，再改回。
4. 把 `WP['grasp']` 的 `'z'` 改为 `1.150`，运行并记录 `[1002]`；改回后确认恢复。
5. 把 `WP['grasp']` 的 `'rx'` 改成 `0`，运行观察夹爪朝向（工具 z 朝上），最后恢复 `3.1416`。

### 3.4 编程提示
- 一次只改一个分量；rx/ry/rz 同时改，反解容易失败。
- 反解第二个参数是"参考关节角"，参考值离目标越近，解越稳定。
- 打印度数时用 `round(x*180/3.1416, 1)`，便于和示教器对照。

### 3.5 调试检查点
| 现象 | 优先检查 | 判定 |
| --- | --- | --- |
| 提示 `[1002]` | `WP` 的 z 是否超出臂展、姿态是否过于倾斜 | 改回默认值能跑通 |
| 夹爪朝向不对 | `rx` 是否被改动（0 表示朝上） | 恢复 3.1416 |
| 反解结果与 Q 差别很大 | 是否把 `Q`/`WP` 的键写串 | 用 `Q['grasp']` 而非 `Q['approach']` |
| `pose_trans` 结果不符合直觉 | 偏移是否写成了基座系 | 记住偏移是工具系 |

### 3.6 预期现象
- `APPROACH_OFFSET.z` 增大 → 打印的接近点沿工具方向抬升，实际抓取路径不变（它只是校核值）。
- `rx=0` → 夹爪翻转朝上，抓取时无法夹住工件（夹爪朝天）。
- `z=1.150` → 立即 `[1002]`，机械臂停在上一位置。

### 3.7 验收标准
1. 能写出正解/反解各一次调用，并解释返回值含义。
2. 完成"偏移量改变 → 接近点变化"的对照，附两组数值。
3. 复现并解释 `[1002]`。
4. 说明为什么机器人不能在所有位姿下抓取（可达性 + 奇异点）。

### 3.8 实验界面应展示
- **知识卡**：基座系/工具系示意图；`pose_trans` 与直接改 z 的对比图。
- **引导**：五步流程卡，每步给出"改哪里 → 看什么数值"。
- **提示**：改动 `rx` 时提示"这会让夹爪翻转"；出现 `[1002]` 时提示"先改回 z 再试"。
- **反馈**：日志中同时打印关节角（rad 与 deg）与 TCP，便于对照。

## 实验四　节拍与轨迹优化（中等，60–90 min）

### 4.1 实验目标
1. 把单件节拍压到 5 s 以内且成功率保持 100%。
2. 说清 `t>0`（定时）与 `a/v`（调速）两种控制方式，知道二者互斥。
3. 理解交融半径 `r` 的作用：让相邻路径点提前过渡，缩短节拍但会切角。
4. 会用"只改一个变量"的方法做对比实验，并记录数据。

### 4.2 相关知识
- 节拍 = 一次完整取放的耗时；日志与右栏都会显示。
- 夹爪开合固定约 0.6 s，是节拍下限的重要组成。
- `TRANSIT_Z` 越高越安全，但 Z 行程增加会拉长节拍。
- `r` 过大会让路径切角，抓取/放置点附近应保持 `r=0`。

### 4.3 任务流程
1. 默认参数连续跑 3 次，记录基线节拍。
2. 只改 `T_JOINT=0.800`、`T_LINEAR=0.350`，再跑 3 次。
3. 把两个 `T_*` 都设为 0，改用 `A_JOINT=1.0 / V_JOINT=1.2 / A_LINEAR=0.6 / V_LINEAR=0.3` 驱动。
4. 设 `R_LINEAR=0.020`，打开「轨迹」观察拐角是否圆滑。
5. 把 `TRANSIT_Z` 降到 0.200，比较节拍与碰撞风险，选出最优组合并写出理由。

### 4.4 编程提示
- 记录数据用表格：参数组合 / 3 次节拍 / 成功率。
- 改动 `t` 后 `a/v` 不再生效，别再同时调它俩。
- 想再快，先看日志里哪一段最慢（接近/转运/放置）。

### 4.5 调试检查点
| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 节拍没变化 | 改的 `a/v` 在 `t>0` 时不生效 | 把 `t` 改为 0 |
| 抓空/撞件 | 降 `TRANSIT_Z` 太多 | 回到 0.24 以上 |
| 轨迹切角撞盒 | `r` 过大 | 抓放点附近设 0 |
| 连续失败 | 节拍过快导致夹爪没夹稳 | 夹紧后等待 0.4 s |

### 4.6 预期现象
- `t` 减半 → 节拍明显下降，但启停冲击变大。
- `t=0` 且 `a/v` 增大 → 节拍继续下降，运动更"急"。
- `r>0` → 轨迹拐角变圆，节拍略降。
- `TRANSIT_Z=0.20` → 节拍下降，但大件通过性变差。

### 4.7 验收标准
1. 最佳节拍 ≤ 5.0 s，且连续 3 次成功。
2. 提交至少 3 组参数对比表（含成功率）。
3. 解释 `t` 与 `a/v` 的互斥关系。
4. 给出你选择的最终参数与理由（速度 vs 安全）。

### 4.8 实验界面应展示
- **知识卡**：速度曲线示意（梯形/定时）；`r` 的交融效果图。
- **引导**：对照实验模板（基线 / 定时优化 / 调速优化 / 平滑）。
- **提示**：`t>0` 时在代码面板提示"a/v 当前无效"。
- **反馈**：最佳节拍、连续成功次数实时显示；轨迹开关一键对比。

## 实验五　满盒装箱与放置精度（中高，90–120 min）

### 5.1 实验目标
1. 把 4 件不同形状的工件稳定放入同一料盒的 4 个槽位，并说明槽位分配策略。
2. 理解放置点 (x, y)、yaw 与盒内干涉的关系。
3. 通过 `PLACE_Z` 的微调，观察"压边 / 悬空掉落 / 姿态偏移"三种失败。
4. 统计装载率与成功率，形成可复用的装箱规则。

### 5.2 相关知识
- A/B 盒各有 4 个槽位（±60 mm × ±45 mm），平台按放置顺序轮换。
- 放置点由 `WP['place']` 决定，`rz` 决定工件朝向；相邻件 yaw 差过大会互相顶住。
- 大件（L 形块、六棱柱）优先占角落，小件补空位，能减少干涉。
- 放置高度过低会压盒底，过高会自由落体导致姿态不可控。

### 5.3 任务流程
1. 放 1 个小件进 A 盒，确认它落在哪个槽位。
2. 连续放 4 件，记录每件落点与朝向。
3. 用 L 形块 + 六棱柱与小件混装，观察是否干涉。
4. `PLACE_Z` +0.02 与 −0.02 各试一次，记录姿态差异。
5. 统计：A 盒件数、成功率、平均节拍，写出你的槽位分配策略。

### 5.4 编程提示
- 一次只放一件，等节拍结束再放下一个。
- 放之前确认夹爪张开到 100%（`set_claw(20, 100)`）。
- 大件放角落、yaw 取 0 或 ±0.1，减少斜放。

### 5.5 调试检查点
| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 工件压在盒沿 | 放置点偏出盒内 12 mm | 检查 `WP['place']` 的 x/y |
| 两件互相顶住 | yaw 差过大 / 槽位重叠 | 降低 yaw、按槽位顺序放 |
| 掉落姿态歪 | `PLACE_Z` 偏高 | 降低 0.02 |
| 夹爪带起工件 | 张开幅度不够 | `GRIP_OPEN_AMP=100` |

### 5.6 预期现象
- 4 件依次落入 4 个槽位，互不接触；大件在角落更稳。
- `PLACE_Z` 偏高时，工件落地后朝向随机偏移，甚至压到邻件。
- 混装时若先放小件再放大件，容易挤压。

### 5.7 验收标准
1. A 盒放满 4 件，且 4 次内完成（尝试 ≤ 5）。
2. 至少包含 2 种形状。
3. 提交槽位分配图（哪件放哪个槽、yaw 多少）。
4. 能解释一次放置失败的原因。

### 5.8 实验界面应展示
- **知识卡**：4 槽位坐标图；yaw 与干涉示意。
- **引导**：装箱顺序建议（大件先、角落优先）。
- **提示**：放置点越界时提示"已超出盒内边距"。
- **反馈**：料盒内实时件数、槽位占用图、成功率。

## 实验六　示教编程与安全流程（高，90–120 min）

### 6.1 实验目标
1. 完成"手动示教 → 记录 → 回放"，并与同任务的代码编程做对比。
2. 演练急停 → 复位 → 继续运行，理解 `ESTOP` 状态机。
3. 说明协作机器人为什么必须限速、留安全余量，给出自己的安全建议。
4. 能定量比较两种编程方式的精度、节拍与可复用性。

### 6.2 相关知识
- 示教记录的是关节角序列，回放按关节插值；代码可精确给位姿、速度、交融参数。
- 急停后所有运动指令都会报 `[1003]`，必须先 `stop_sys()` 再 `start_sys()`。
- 协作机器人安全策略：限速、限力、安全平面、减少夹持点悬伸。
- 节拍不是越快越好：速度越高，惯性冲击越大，重复精度越差。

### 6.3 任务流程
1. 切到「手动示教」，把机械臂拖到抓取位上方，记录 3 个示教点。
2. 点「回放示教」，记录轨迹形状与耗时。
3. 用代码 `movej` 实现同一路径，比较两者的精度与耗时。
4. 代码运行途中点「急停」，再点「复位」，确认能继续。
5. 把 `T_JOINT` 减半再运行，比较冲击与成功率，写出安全建议（3 条以内）。

### 6.4 编程提示
- 示教点越多轨迹越平滑，但回放时间更长。
- 急停后不要直接发运动指令，先复位。
- 对比实验固定其他参数，只改一个变量。

### 6.5 调试检查点
| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 回放没反应 | 没记录示教点 | 至少记录 1 个点 |
| 提示 `[1003]` | 急停未复位 | 点「复位」 |
| 示教轨迹抖动 | 点数太少 / 拖动过快 | 多点、慢拖 |
| 提速后失败率上升 | 夹爪未夹稳就开始提升 | 增加夹紧等待 |

### 6.6 预期现象
- 示教回放轨迹与拖动路径基本一致，但点位精度依赖拖动。
- 急停时状态灯变红 `ESTOP`，程序提示"运动被停止"；复位后立即恢复。
- `T_JOINT` 减半后节拍下降约 20–30%，但停止时的晃动更明显。

### 6.7 验收标准
1. 记录 ≥ 3 个示教点并完成回放。
2. 完成一次急停 → 复位 → 继续运行。
3. 提交示教 vs 代码的对比表（精度 / 节拍 / 复用性）。
4. 给出 3 条安全建议，并与平台参数对应。

### 6.8 实验界面应展示
- **知识卡**：示教-回放流程图；`ESTOP` 状态机与复位路径。
- **引导**：对比实验模板（同一路径，两种实现）。
- **提示**：进入示教模式时提示"拖动关节前先确认周围无障碍"。
- **反馈**：示教点数、回放耗时、急停次数、当前状态灯。
